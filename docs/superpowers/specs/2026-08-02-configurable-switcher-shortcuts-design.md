# 전환 모드 단축키 통합 설정 설계

**날짜:** 2026-08-02
**상태:** 승인됨

## 목표

SwitchTab의 두 전환 모드를 동일한 설정 구조와 UI로 관리한다.

- `Current App Windows`: 기본 `Cmd + \``
- `Application Switching`: 기본 `Cmd + Tab`
- 두 모드 모두 활성화 토글, 단축키 녹화, 기본값 초기화를 제공한다.
- 신규 설치에서는 두 모드가 모두 활성화된다.
- 기존 설치에서는 저장된 단축키와 앱 전환 활성 상태를 최대한 보존한다.
- 토글을 꺼도 저장된 단축키를 보고 수정할 수 있다.

## 비목표

- 전환 오버레이의 디자인이나 선택 규칙은 바꾸지 않는다.
- 현재의 윈도우 전환 HotKey 등록기와 앱 전환 EventTap 등록기를 하나로 합치지 않는다.
- 여러 단축키 프로필이나 모드별 복수 단축키는 추가하지 않는다.

## 사용자 인터페이스

Shortcuts 패널에 동일한 형식의 행 두 개를 표시한다.

1. `Current App Windows`
2. `Application Switching`

각 행의 오른쪽에는 다음 순서로 컨트롤을 둔다.

1. `Enabled` 또는 `Disabled` 상태 텍스트
2. macOS 표준 토글
3. 현재 단축키를 표시하는 녹화 버튼
4. 기본값 초기화 버튼

토글이 꺼져도 녹화 버튼과 초기화 버튼은 활성 상태를 유지한다. 검증 오류, 등록 실패, 권한 부족 메시지는 해당 모드 행 바로 아래에 표시한다. 행 높이와 패널 높이는 상태 변경으로 달라지지 않는다.

## 데이터 모델

두 모드를 하나의 모델로 표현한다.

```swift
struct SwitcherShortcutConfiguration: Codable, Equatable, Sendable {
    let mode: SwitcherMode
    var isEnabled: Bool
    var shortcut: ShortcutSetting
}
```

`ShortcutSettingsStore`는 두 설정을 하나의 버전이 있는 payload로 저장하고 로드한다. `ShortcutSettingsViewModel`은 두 설정의 토글, 녹화, 초기화, 오류 상태를 관리한다. `ApplicationSettingsViewModel`에서는 기존 앱 전환 토글 책임을 제거한다.

설정 모델과 UI는 통합하지만 실제 등록기는 분리한다.

- 윈도우 전환은 기존 일반 전역 단축키 등록기를 사용한다.
- 앱 전환은 Command 키 릴리즈와 역방향 전환을 처리하는 기존 EventTap 등록기를 사용한다.

## 기본값과 마이그레이션

신규 통합 payload가 없으면 기존 키에서 한 번 마이그레이션한다.

- 윈도우 단축키: 기존 저장값 또는 `Cmd + \``
- 윈도우 활성 상태: `true`
- 앱 단축키: `Cmd + Tab`
- 앱 활성 상태:
  - 기존 `replacesCommandTab` 값이 명시적으로 저장되어 있으면 그 값을 사용한다.
  - 기존 SwitchTab 설정, 단축키, MRU, 사용 기록이 있으면 기존 설치로 보고 `false`를 사용한다.
  - 알려진 기존 데이터가 전혀 없으면 신규 설치로 보고 `true`를 사용한다.

구버전 기본값 `false`는 저장되지 않았으므로, 전혀 사용하지 않은 기존 설치와 신규 설치는 완벽하게 구분할 수 없다. 전혀 기록이 없는 기존 설치는 신규 설치로 분류될 수 있다. 통합 payload를 저장한 뒤에는 이 추론을 다시 실행하지 않는다. 기존 키는 이전 버전 롤백을 위해 삭제하지 않는다.

## 설정 변경 흐름

### 활성화 변경

1. 사용자가 토글을 변경한다.
2. ViewModel이 후보 통합 설정을 저장한다.
3. AppDelegate가 변경된 모드의 등록기를 갱신한다.
4. 활성화 실패 시 설정은 활성 상태로 유지하고 해당 모드에 복구 메시지를 표시한다. 등록되지 않은 단축키는 시스템 입력을 소비하지 않는다.
5. 비활성화된 모드의 오버레이가 열려 있으면 닫는다.

### 단축키 녹화

1. 녹화 시작 시 두 모드의 전역 등록을 잠시 해제한다. EventTap이 녹화 입력을 먼저 소비하지 않게 한다.
2. Escape는 변경 없이 녹화를 종료한다.
3. 입력을 `ShortcutCapture`로 변환한다.
4. modifier 존재 여부, macOS 사용 가능 여부, 다른 모드와의 물리 키 중복을 검사한다.
5. 저장 전에 후보 단축키와 자동 생성한 Shift 역방향 단축키를 등록한다.
6. 성공하면 통합 설정을 저장하고 UI를 갱신한다.
7. 실패하면 저장값을 건드리지 않고 이전 등록을 복원한 뒤 해당 모드에 오류를 표시한다.
8. 녹화 종료 시 활성화된 두 모드를 현재 저장값으로 복구한다.

앱 전환의 역방향 단축키는 사용자가 지정한 정방향 단축키에 `Shift`를 추가해 생성한다. 예를 들어 `Option + Space`의 역방향은 `Option + Shift + Space`다.

## 검증과 충돌 처리

- 단축키에는 최소 한 개의 modifier가 필요하다.
- 두 모드는 같은 물리 키와 modifier 조합을 사용할 수 없다.
- 앱 전환의 정방향과 자동 생성된 역방향 조합도 다른 모드와 충돌할 수 없다.
- 단축키가 동일한 값으로 다시 저장되면 저장이나 재등록을 수행하지 않는다.
- 초기화는 해당 모드의 기본 단축키만 복원하며 활성 상태는 바꾸지 않는다.

## 테스트

자동 테스트는 다음을 증명한다.

- 신규 설치 기본값은 두 모드 모두 활성화다.
- 기존 윈도우 단축키와 명시적 앱 전환 상태가 마이그레이션된다.
- 기존 사용 기록만 있는 설치는 앱 전환 비활성 상태로 마이그레이션된다.
- 통합 payload가 있으면 마이그레이션을 반복하지 않는다.
- 토글 변경, 단축키 저장, 초기화가 다른 모드 상태를 바꾸지 않는다.
- 비활성 상태에서도 단축키를 편집할 수 있다.
- 두 모드 간 중복과 역방향 충돌이 거부된다.
- 등록 실패 시 이전 설정과 등록이 복원된다.
- 녹화 중 두 등록기가 해제되고 종료 후 활성 모드만 복원된다.
- 앱 전환 등록기는 저장된 정방향 단축키와 Shift 역방향을 사용한다.

실제 macOS QA는 다음을 확인한다.

- 두 토글의 `Enabled/Disabled` 상태와 고정된 행 높이
- 두 키캡의 녹화 및 Escape 취소
- `Cmd + \`` 윈도우 전환과 `Cmd + Tab` 앱 전환
- 각 모드 비활성화 시 native 입력 복원
- 꺼진 상태에서 단축키 편집 후 재활성화
- 앱 재시작 후 두 활성 상태와 단축키 유지
- Command 릴리즈와 마우스 선택 시 실제 대상 윈도우/앱 활성화
