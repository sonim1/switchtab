# SwitchTab: 기능, 측정, 호환성 후속 검토

기준: 공개 1.1.31 (42), 소스 `37a56da`. 확인일: 2026-10-14.
이 문서는 개선 제안과 실제 검증 결과를 구분한다. 앱 기능을 새로 추가한
릴리스가 아니다. 이번 수정은 검증 범위를 넘어선 랜딩의 Spaces 설명이다.

## 1. 기능·사용성: 다음에 무엇을 개선할 것인가

선택·확정·MRU 알고리즘을 다시 바꾸기보다, 동작이 불가능한 이유와 첫 사용
성공 여부를 알리는 흐름을 우선한다. 아래 항목은 사용자 조사로 검증된 수요가
아닌, 현재 소스와 네이티브 QA에 근거한 제품 개선 후보다.

| 우선순위 | 관찰 / 근거 | 제안 | 완료 조건과 회귀 위험 |
| --- | --- | --- | --- |
| P1, 이번 수정 | 랜딩은 Spaces·보조 화면의 창을 어디서든 가져오는 듯 설명했다. 기존 fullscreen QA에서는 macOS AX 목록 자체가 현재 fullscreen 창 하나만 반환했다. | 사용 가능한 창·최소화 복원을 설명하고 다른 Space의 창이 목록에 없을 수 있음을 명시. | 실제 동작 이상을 약속하지 않는다. 설치 링크·레이아웃은 유지. |
| P1, 다음 앱 개선 | `AppDelegate.presentWindowSwitcher`는 유지 중인 세션에서 창 목록이 비면 기존 세션을 보존하고 false를 반환한다. 사용자는 모드 전환이 왜 안 되는지 알기 어렵다. | 선택 앱에 사용 가능한 창이 없다는 짧은 비모달 안내. 접근성 권한 부족과 창 없음은 구분. | 기존 세션·선택·modifier 유지, release는 기존 선택 확정, Escape 취소. 안내가 키 입력을 가로채거나 앱을 활성화하지 않고 VoiceOver에도 중복 없이 전달돼야 함. |
| P1, 다음 앱 개선 | Practice는 정확한 창 포커스를 검증하지만 결과를 보려면 How to Use를 다시 열어야 한다. `SwitchingGuideView`에 이 절차가 명시돼 있다. | 전환을 방해하지 않는 성공 확인과 복구 가능한 실패 안내를 설계. 시작 버튼에서 이전 앱·다중 창 조건을 더 명확히 설명. | 요청 성공만으로 완료 처리하지 않는다. 실제 포커스 확인 후만 완료, 취소는 미완료. 자동으로 Settings를 앞으로 가져오지 않는다. |
| P2 | 홈 화면에서 설치 버튼은 설치 섹션으로 이동하고, DMG 버튼은 GitHub 릴리스 페이지로 이동한다. 390px 화면에서 모두 읽히며 가로 넘침이 없다. Homebrew 명령은 선택 가능한 코드이며 복사 버튼은 없다. | 비개발자용 DMG 설치 경로와 Homebrew 경로를 비교해 사용성 테스트. 복사 버튼은 성공/실패 상태·키보드 사용까지 포함해 필요성을 판단. | 지원 아키텍처·OS와 보안 검증 안내 유지. 단순 클릭 수를 설치 성공으로 표시하지 않음. 현재 흐름은 고장으로 분류하지 않음. |
| P2 | 창 제목은 시각적으로 축약되고 AX 이름은 전체 제목이다. 창이 많을 때 검색 수요는 아직 측정되지 않았다. | 먼저 10/30/50개 소유 창에서 선택 시간·스크롤·메모리를 측정한 뒤 검색/필터 도입 판단. | 키 입력과 사용자 지정 단축키의 충돌, MRU와 검색 결과의 순서를 설계하기 전 검색 기능을 추가하지 않음. |
| P3 | About 사용 횟수는 창을 열 때의 스냅샷이며 반복·취소도 포함한다. 현재 설명은 정확하다. | 실시간 갱신은 실제 요구가 있을 때만 시행. | 저장 키·집계 의미 유지, 보이는 동안만 갱신. 다운로드/활성 사용자 통계로 바꾸지 않음. |

추천 순서는 **호환성 설명 정정 → 빈 목록 안내 → Practice 피드백 → 큰 목록
성능 측정**이다. 앱별 예외 규칙, 전역 검색, 계정, 원격 앱 추적은 이번 근거만으로
추가할 이유가 부족하다. 새 추상화나 전환 로직 전면 리팩터링도 제안하지 않는다.

## 2. 방문·다운로드 측정: 실제 확인한 것

| 측정 단계 | 결과 | 해석 |
| --- | --- | --- |
| 운영 홈페이지 HTML | Cloudflare 비콘 1개 | 중복 수집 스니펫 없음. 수동 스니펫 추가 불필요. |
| 실제 Chromium 네트워크 | 비콘 JS 200, `cloudflareinsights.com/cdn-cgi/rum` POST 204 | 실제 페이지에서 수집 endpoint까지 전송 성공. CSP 오류 없음. |
| 가이드 페이지 | 동일 수집 endpoint POST 204 | 홈페이지 이외 페이지도 수집 경로 정상. |
| Cloudflare 대시보드 | 기존 Chrome 세션이 로그인 화면으로 이동 | 기간별 방문/페이지뷰·유입 집계는 미확인. 전송 성공을 보고서 반영 성공으로 대체하지 않음. |
| GitHub 공개 정식 릴리스 DMG | 38개 릴리스의 `download_count` 합계 123, 최신 1.1.31은 4 | 조회 시점 누계. QA·Homebrew 자동 검증·재다운로드가 섞이며 고유 사용자/설치 수가 아님. 삭제된 자산과 R2 다운로드는 포함하지 않음. |
| 설치 버튼 전환 | 별도 이벤트 수집 없음 | 방문→DMG 클릭→설치 전환율을 현재 데이터로 계산할 수 없음. |
| 실제 설치/활성 사용자 | 앱 텔레메트리 없음 | 미측정. 0명이라는 의미가 아님. |

이번 브라우저 QA 방문과 기존 릴리스 검증 다운로드도 통계에 영향을 줄 수 있다.
소규모 트래픽에서 검증 요청을 실제 신규 사용자 성장으로 해석하지 않는다.

### 운영 방식

1. 매주 같은 UTC 시각에 Cloudflare에서 Host=`switchtab.royjen.com`, 봇 제외,
   최근 28일/이전 28일 조건으로 방문·페이지뷰·경로·referrer·기기와 집계 기간을 기록한다.
2. GitHub는 자산 ID별 누계를 저장하고 다음 스냅샷과 차이를 계산한다. 릴리스
   개수·조회 시각·QA/자동 검증 여부도 함께 기록한다. 총합 변화만으로 사용자를 추정하지 않는다.
3. R2/Sparkle 경로는 별도 다운로드 채널이다. appcast 조회는 업데이트 확인이지
   DMG 다운로드가 아니며, DMG 요청에도 재시도와 부분 요청이 섞일 수 있다.
4. 방문 수 대시보드 확인이 먼저다. 새로운 수집 서비스를 추가하기 전에 현재
   지표로 어느 결정을 내릴 것인지 정한다.

재현 가능한 공개 다운로드 조회:

```sh
rtk gh api --paginate 'repos/sonim1/switchtab/releases?per_page=100' \
  --jq '.[] | select(.draft == false and .prerelease == false) | {tag: .tag_name, assets: [.assets[] | select(.name | endswith(".dmg")) | {id, name, download_count}]}'
```

Cloudflare Web Analytics는 현재 custom events와 UTM 보고를 제공하지 않는다.
데이터는 6개월 동안 조회 가능하고 오래된 집계에는 샘플링이 적용될 수 있다.
[공식 FAQ](https://developers.cloudflare.com/web-analytics/faq/).

클릭 전환이 제품 의사결정에 필요해지면 선택지는 세 가지다:

- **현재 수집 유지 + 정기 스냅샷(지금 추천):** 추가 개인정보 수집과 운영 비용
  없이 실제 유입 기준선을 만든다. 버튼 클릭/설치는 알 수 없다.
- **랜딩에 최소 이벤트 수집:** `download_click`와 `install_command_copy`처럼
  정의된 웹 이벤트만 수집한다. 수집처·보관 기간·privacy notice·CSP 변경과 검증이
  먼저 필요하다. 앱 이름/창 제목·기기 식별자·전체 URL query는 보내지 않는다.
- **서버 측 다운로드 경로 집계:** 다운로드 경로에 운영 의존성이 생기고 봇/프리페치/
  재시도를 분리해야 한다. 클릭이나 설치 완료를 증명하지 않는다.

이번에는 새 이벤트 endpoint, 쿠키, 앱 텔레메트리를 추가하지 않았다.

## 3. 호환성: 공개 릴리스와 현재 장비의 재검증

환경: Apple M1, macOS 26.5.1 (25F80), 온라인 내장 Retina 화면 1대.
GitHub 공개 1.1.31 (42) DMG에서 추출한 앱을 기존 서명·경로로 실행했다.
기존 TCC 권한을 유지했고 사용자 문서 대신 소유된 테스트 앱을 사용했다.

| 시나리오 | 이번 결과 |
| --- | --- |
| 창 선택 이동 → 취소 → 재열기 | 통과. 원래 창과 다음 MRU 선택 유지. |
| 앱 선택 이동 → 취소 → 재열기 | 통과. 원래 창·앱 유지. |
| 앱 → 선택 앱의 창 → 앱 handoff | 통과. 누른 modifier 세션 유지, 취소 시 원래 창 유지. |
| Return 확정 | 선택 후 소유 창 A 활성화, 오버레이 종료 관찰. |
| 앱 타일 AXPress | 지정한 view fixture 앱이 정확히 활성화됨. |
| 최소화 복원 | 소유 창 B의 AXMinimized true → false, AXMain true 확인. |
| 선택 창 닫기 | 소유 대상만 목록에서 제거되고 나머지 2개 유지, 세션 유지 후 취소. |
| 선택 앱 종료 | 소유 fixture 종료, 타일 제거, fixture-running=false 확인. |

8개 bounded driver 실행 모두 종료 코드 0. 원본 출력은 무시되는 로컬
`.omo/evidence/product-followup-2026-10-14/`에 보관한다. 이 드라이버의 AX
검사는 VoiceOver 실제 발화를 대신하지 않는다. 실제 발화는 이전
[접근성 후속 검증](accessibility-compatibility-audit-2026-10-14.md)의 별도 증거를 따른다.

### 아직 통과로 기록할 수 없는 환경

| 환경 | 필요한 입력/장비 | 수행할 체크와 통과 조건 |
| --- | --- | --- |
| macOS 14 / 15 | 각 OS의 Apple silicon Mac 또는 사용 가능한 해당 macOS GUI VM | 동일 서명 릴리스의 8개 시나리오, VoiceOver 재열기/닫기, Settings 기록 취소, 권한 복구 안내. Swift 컴파일만으로 GUI 호환 통과 처리하지 않음. |
| 물리 화면 2대 이상 | 외부 화면, 혼합 배율, 좌/우/상/하 배치 | 포인터 화면에서 오버레이가 보이는 영역 안에 배치됨. 선택·release·취소 정확성. 열어 둔 상태에서 분리/주 화면 변경 시 화면 밖에 남거나 중복 확정되지 않음. |
| Spaces/fullscreen | 각 OS에서 소유 창의 별도 Space 배치 | raw AX 창 목록과 오버레이를 함께 기록. OS가 제공하지 않은 창은 앱 필터 결함으로 집계하지 않음. 제공된 창을 선택할 때 정확한 창 활성화 확인. |
| 저장 대화상자가 있는 앱 종료 | 저장하지 않은 소유 문서 fixture | 취소 시 앱/타일 유지, 저장 후 실제 종료 때만 타일 제거. 사용자 작업 중인 문서로 실행하지 않음. |

음수 화면 좌표·수직 배치·빈 화면 fallback의 기존 회귀 테스트는 유지된다.
현재 장비만으로 물리 다중 모니터나 다른 OS를 시험한 것으로 표시하지 않는다.

검증 후 modifiers 해제, 두 fixture 종료, 원래 설치 앱을 복구했다. strict 서명과
원본 실행 파일 SHA-256 일치를 확인했다. 사용자 설정과 TCC는 초기화하지 않았다.

## 다음 실행 단위

1. Cloudflare 로그인 복원 후 실제 방문 집계·필터·조회 기간을 기록한다.
2. 빈 창 목록 안내와 Practice 피드백을 각각 작은 변경으로 설계하고 회귀를 검증한다.
3. 다른 OS·추가 화면이 준비되면 위 matrix를 실행한다. 준비 전에는 검증 범위를
   확대했다고 주장하거나 이를 이유로 전환 알고리즘을 추측 수정하지 않는다.
